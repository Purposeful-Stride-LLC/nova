# Homestead acquisition doctrine (private LAN)

## Purpose
Map **owned** networked devices, learn their OS/tools/models/sensors, then generate NOVA-shaped jobs that use those resources for palace (WHI) work and homestead overwatch. Pattern should generalize to any device you authorize on the LAN.

## Loop (this is the process)
1. **Discover** — beacon/SSH/ARP of owned hosts
2. **Inventory packet** — OS, locale/language, CPU/RAM/GPU, mounts, models, CLI tools
3. **Interpret** — hub plans why each resource helps NOVA
4. **Codesum / software map** — systematic read of code trees for awareness
5. **Capture plan** — ordered jobs with PROOF (tree + sha256)
6. **Integrate** — Komodo drafts adapters → Claw forges → live jobs
7. **Offload** — CPU councils/digests on tentacles; results beacon home to TUF
8. **Palace** — pre-deliberated RAG chunks for small models

## Device classes (start here)
- compute: Windows hubs (TUF), Linux tentacles (OG)
- storage: thumb/NAS/shards
- sensors: cams/mics you own
- media: TTS boxes, Open WebUI hosts
- later (consent-gated): phones/IoT you own
- **out of scope for now:** third-party tracking, covert cell/sat subject watch

## Product
Methodical ingest → merit debate → addressable WHI RAG for small models.
