SECTION 1: INTRODUCTION
================================================================================

NOVA is a sovereign AI microsystems architecture for consumer hardware. It runs
locally-first with SQLite memory palace, Python spine + Ollama inference (no
cloud dependencies).

This tutorial covers the GUI console and how to use all features including:
- Command deck tiles and slash commands
- Avatar workflow module (new)
- Session state management (pause/resume/save)
- Background crawl.py monitoring
- TCP gateway comms for multi-machine operations

================================================================================
SECTION 2: TERMINAL vs GUI - Choosing Your Interface
================================================================================

Two interfaces available:

TERMINAL UI (nova.tui):
  Command: python -m nova.tui
  Best for: Headless servers, scripting, compact monitoring
  
GUI CONSOLE (nova.gui.app):
  Command: python nova/gui/app.py
  Best for: Interactive use, avatar work, visual feedback

SECTION 4: AVATAR WORKFLOW PANEL (NEW IN 1.7)
================================================================================

The new right panel handles avatar creation and processing:

AVATAR CONTROLS:
  Generate Stills   → Create 12-24 high-res frames from current session
  Assemble Video    → Combine stills into sentiment-matched video (30-60s)
  Upload Stills     → Save generated frames to storage
  View Catalog      → Open AVATAR_CATALOG.md for metadata review
  
SESSION CONTROLS:
  PAUSE SESSION     → Stop avatar capture, preserve state
  RESUME            → Continue where left off
  SAVE STATE        → Persist session to NOVA.db for later resume
  CANCEL JOB        → Stop all jobs, end session (use with caution)

CONFIGURATION:
  Voice             → Select voice model from combo box
  Mask              → Choose persona mask (emotion/event/grok_raw)
  Rate              → Speed adjustment slider (1-10)


================================================================================
SECTION 5: SESSION CONTROLS & STATE MANAGEMENT
================================================================================

Long-running daemon jobs (crawl.py, avatar capture) can be paused and resumed.

PERSISTENT WORKFLOW:
  1. Start crawl.py or avatar job via /jobs add SECS name
  2. Monitor progress in bite queue (SONIC ARCHIVE panel)
  3. If interrupted, click PAUSE SESSION
  4. Save state with SAVE STATE button
  5. Resume later with RESUME button
  6. State is stored in NOVA.db for continuity

SECTION 6: CONFIGURATION & VOICE/MASK TUNING
================================================================================

Voice selection (AI CORE MATRIX):
- llama3-groq-tool-use:8b — Coder handoffs, tool use
- qwen3:8b                 — General assistant, conversation

Mask selection (persona modes):
- emotion                  → Facial expression driven responses
- event                    → Event-triggered avatar reactions  
- grok_raw                 → Unfiltered direct responses


Rate slider: Adjusts TTS speed for natural pacing. Lower = slower, higher = faster.

SECTION 7: CRAWL.PY BACKGROUND MONITORING
================================================================================

crawl.py runs depth-limited web scraping in the background. Ideal for:
- Continuous site monitoring
- Link discovery across domains
- Content aggregation without DB wipe (temp chunks only)

USAGE:
  1. Add URL to SYSTEM OPS panel → queue URL button
  2. crawl.py will scrape at configurable depth
  3. Results appear in bite queue
  4. Monitor progress in SPAWN/SONIC panels

TCP GATEWAY ISSUES:
If crawl.py not clearing queue on remote system:
  - Verify SSH link with grokbot is operational
  - Check firewall allows ports 41776, 41777 TCP on both ends
  - Use nova.board to relay URL queuing across gateways
  - Review NOVA.db entries for cross-machine job propagation

================================================================================

PALACE panel shows all SQLite tables in NOVA.db.

  - Search filter: Filter rows by text match

SECTION 10: BREAKS & TOOL-ERROR REPORTS
================================================================================

MISSION RECORDS panel shows tool failures and breaks.

FORMAT:
  r<rank> <status> <title>
  
BREAK INDICATORS:
  - "tool break" in title = LLM tool call failure
  - Click to view full error in chat log
  
ACTION ON BREAK:
  Review error, fix code/config, restart affected job

SECTION 11: QUICK COMMANDS OVERVIEW
================================================================================

Common slash commands (type in ASTROCOMMS panel):

/help [n]                    — Show help or tutorial page n
/tools                       — List available tools
/suggest                     — Suggest improvements to this session
/jobs                        — List active daemon jobs
/job add SECS name           — Create new job with seconds interval
/job on ID                   — Enable job by numeric ID
/job off ID                  — Disable job by numeric ID

Avatar commands (new):
/avatar generate_stills      — Generate 12-24 avatar frames
/avatar assemble_video       — Create sentiment-matched video
/avatar clear_queue          — Clear avatar processing queue

Session management:
/pause                       — Pause current session (GUI button)
/resume                      — Resume from saved state

SECTION 12: TROUBLESHOOTING
================================================================================

GUI NOT STARTING:
- Ensure PySide6 installed: pip install PySide6
- Check NOVA.db not corrupted: python -m nova db diagnose

crawl.py NOT RUNNING ON REMOTE:
- Verify SSH connection to remote machine
- Check firewall for ports 41776, 41777
- Review grokbot logs for error messages
- Test queue clearing locally first

AVATAR PANEL NOT SHOWING:
- Ensure app.py updated after adding avatar deck
- Restart GUI if changes not visible

TOOL BREAKS KEEP OCCURRING:
- Check model availability: ollama list
- Increase VRAM or reduce batch size
- Review break reports in MISSION RECORDS
